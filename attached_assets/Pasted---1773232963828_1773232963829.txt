ЗАДАЧА: заменить большую модалку ошибки в финальной форме бронирования на лёгкое автоматически закрывающееся уведомление (toast), как на главной странице при выборе дат.

ПРОБЛЕМА:
Сейчас при пустых полях появляется слишком большое всплывающее окно.
Это перегружает UX финального шага бронирования.

ЧТО НУЖНО СДЕЛАТЬ:

1. В финальной форме бронирования оставить проверку полей:
- Имя
- Телефон

2. При нажатии на кнопку "Забронировать номер" проверить заполнение полей:

- если пусты Имя и Телефон:
  показать toast-сообщение:
  "Введите имя и номер телефона"

- если пусто только Имя:
  показать toast-сообщение:
  "Введите имя"

- если пуст только Телефон:
  показать toast-сообщение:
  "Введите номер телефона"

- если оба поля заполнены:
  отправлять форму как обычно

3. НЕ использовать большую модалку по центру с кнопкой.
Вместо этого сделать компактное уведомление в стиле toast/snackbar:

- плавное появление
- плавное исчезновение
- автоматическое закрытие через 2–3 секунды
- без кнопки "Понятно"
- без крестика
- современный минималистичный стиль
- визуально в стиле сайта AL MARE
- по поведению похоже на уведомления на главной странице при выборе дат

4. Размещение toast:
- по центру экрана или чуть выше центра
- не слишком большое
- не перекрывает весь интерфейс тяжёлой модалкой
- можно использовать лёгкий blur/dim background только если это уже используется на сайте, но лучше без тяжёлого затемнения

5. Дополнительно улучшить UX:
- подсветить незаполненные поля красной рамкой
- убрать красную рамку, как только пользователь начал ввод
- после показа уведомления переводить фокус:
  - если пусто Имя → в поле Имя
  - если пуст Телефон → в поле Телефон
  - если пусты оба → сначала в поле Имя

6. Не менять:
- логику отправки формы
- расчёт стоимости
- текст кнопки "Забронировать номер"
- структуру формы

7. Важно:
если toast уже показан и пользователь снова жмёт кнопку, не создавать несколько уведомлений поверх друг друга.
Нужно либо обновлять существующее уведомление, либо показывать только одно активное.

ЦЕЛЬ:
сделать валидацию лёгкой, быстрой и ненавязчивой,
без тяжёлой модалки, но с понятным сообщением пользователю.
